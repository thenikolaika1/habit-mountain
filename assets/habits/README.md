# Фото для карточек привычек

Сюда кладутся реальные фотографии для «Популярные привычки» и баннера
экрана привычки — код в `js/illustrations.js` (`PHOTO_BY_EMOJI`,
`heroIllustrationForHabit()`) уже готов их подхватить, никаких
дополнительных правок не нужно. Достаточно положить файлы сюда с этими
точными именами:

| Файл              | Привычка (эмодзи) |
| ------------------ | ------------------ |
| `pit_vodu.png`      | Пить воду (💧)      |
| `chtenie.png`       | Чтение (📚)         |
| `meditaciya.png`    | Медитация (🧘)      |
| `otzhimaniya.png`   | Отжимания (💪)      |
| `son.png`           | Сон (🛌)            |
| `progulka.png`      | Прогулка (🏃)       |

## Как это работает

- `heroIllustrationForHabit(habit)` сначала проверяет, есть ли у эмодзи
  привычки (`habit.icon`) фото в `PHOTO_BY_EMOJI`; если да — рендерит
  `<img src="./assets/habits/<файл>">`, иначе — как раньше, рисованную
  SVG-сцену (`heroXxx()`).
- Привычка **любого** имени с одним из этих шести эмодзи получит то же
  фото — сопоставление идёт по эмодзи, не по названию. Это касается и 6
  готовых пресетов в «Популярные привычки», и любой привычки, которую
  создаст пользователь с тем же эмодзи.
- Фото показывается и в карточке списка привычек, и в карточке
  «Популярные привычки», и в шапке экрана привычки — везде, где раньше
  была нарисованная сцена, один и тот же вызов `heroIllustrationForHabit()`.
- Подпись самого фото (если она есть на картинке) обрезается снизу
  (`~15%` высоты, `.habit-hero-photo` в `css/illustrations.css`) — имя
  привычки приложение рисует само поверх затемняющего градиента, в общем
  стиле остальных карточек.
- Если файл отсутствует или не грузится — `wirePhotoFallback()`
  (вызывается после каждого рендера в `habitsView.js`/`calendarView.js`)
  автоматически подменяет `<img>` на нарисованную SVG-сцену, так что
  карточка никогда не остаётся с сломанной/пустой картинкой.

## Формат

Квадратные (или близкие к квадрату) JPG/PNG, как в референсе — код
обрезает/кадрирует через CSS (`object-fit: cover`), так что небольшие
отличия в пропорциях не критичны. Реальный вес файлов в репозитории не
проверялся — если фото окажутся тяжёлыми, стоит сжать их перед коммитом
(современные форматы вроде WebP тоже подойдут, но тогда нужно поменять
расширения в `PHOTO_BY_EMOJI`, `js/illustrations.js`).

# Фото наград для испытаний

Тот же приём, что и выше, только для карточек «Испытания»/«Достижения» и
шапки экрана Испытаний — код в `js/illustrations.js`
(`MEDAL_BY_CHALLENGE_ID`, `challengeHeroForId()`, `medalHeaderPhoto()`)
уже готов их подхватить.

| Файл                  | Награда         |
| ---------------------- | --------------- |
| `medal_trophy.png`     | Кубок            |
| `medal_shield.png`     | Щит с галочкой   |
| `medal_crown.png`      | Корона           |
| `medal_lightning.png`  | Молния           |
| `medal_star.png`       | Звезда           |

## Как это работает

- `challengeHeroForId(id)` сначала проверяет, есть ли у испытания
  (`CHALLENGE_POOL`'s `id`) награда в `MEDAL_BY_CHALLENGE_ID`; если да —
  рендерит `<img src="./assets/habits/<файл>">` с классом
  `challenge-hero-photo`, иначе — как раньше, рисованную SVG-сцену
  климбера (`challengeHeroXxx()`).
- Один и тот же файл награды может быть привязан к нескольким `id`
  (например, `medal_crown.png` — и к «Половина пути», и к «Упорство») —
  соответствие идёт по смыслу испытания, не 1:1.
- Это же фото используется и на активной карточке испытания (Испытания),
  и на карточке в Достижениях (и завершённой, и незавершённой попытки) —
  везде один и тот же вызов `challengeHeroForId()`.
- Иконка над заголовком «Испытай себя!» — отдельная функция
  `medalHeaderPhoto()`, всегда `medal_star.png`, в том же 72×72 слоте,
  где раньше была SVG-медаль (`medalIllustration()`).
- Исходники — вытянутый портретный кроп (кроме звезды, уже ≈16:9),
  поэтому кадр в широкой карточке (`.challenge-hero-photo`,
  `object-fit: cover`) держит свой `object-position` под каждый файл
  отдельно (`.challenge-hero-photo--trophy/--shield/--crown/--lightning/--star`
  в `css/illustrations.css`), чтобы сама награда не обрезалась.
- Если файл отсутствует или не грузится — та же `wirePhotoFallback()`
  (теперь вызывается и в `challengesView.js`/`achievementsView.js` после
  каждого рендера) подменяет `<img>` на нарисованную SVG-сцену испытания
  или на `medalIllustration()` для шапки — карточка никогда не остаётся
  со сломанной картинкой.
