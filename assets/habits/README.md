# Фото для карточек привычек

Сюда кладутся реальные фотографии для «Популярные привычки» и баннера
экрана привычки — код в `js/illustrations.js` (`PHOTO_BY_EMOJI`,
`heroIllustrationForHabit()`) уже готов их подхватить, никаких
дополнительных правок не нужно. Достаточно положить файлы сюда с этими
точными именами:

| Файл              | Привычка (эмодзи) |
| ------------------ | ------------------ |
| `pit_vodu.png`      | Пить воду (💧)      |
| `chtenie.png`       | Чтение (📚)         |
| `meditaciya.png`    | Медитация (🧘)      |
| `otzhimaniya.png`   | Отжимания (💪)      |
| `son.png`           | Сон (🛌)            |
| `progulka.png`      | Прогулка (🏃)       |

## Как это работает

- `heroIllustrationForHabit(habit)` сначала проверяет, есть ли у эмодзи
  привычки (`habit.icon`) фото в `PHOTO_BY_EMOJI`; если да — рендерит
  `<img src="./assets/habits/<файл>">`, иначе — как раньше, рисованную
  SVG-сцену (`heroXxx()`).
- Привычка **любого** имени с одним из этих шести эмодзи получит то же
  фото — сопоставление идёт по эмодзи, не по названию. Это касается и 6
  готовых пресетов в «Популярные привычки», и любой привычки, которую
  создаст пользователь с тем же эмодзи.
- Фото показывается и в карточке списка привычек, и в карточке
  «Популярные привычки», и в шапке экрана привычки — везде, где раньше
  была нарисованная сцена, один и тот же вызов `heroIllustrationForHabit()`.
- Подпись самого фото (если она есть на картинке) обрезается снизу
  (`~15%` высоты, `.habit-hero-photo` в `css/illustrations.css`) — имя
  привычки приложение рисует само поверх затемняющего градиента, в общем
  стиле остальных карточек.
- Если файл отсутствует или не грузится — `wirePhotoFallback()`
  (вызывается после каждого рендера в `habitsView.js`/`calendarView.js`)
  автоматически подменяет `<img>` на нарисованную SVG-сцену, так что
  карточка никогда не остаётся с сломанной/пустой картинкой.

## Формат

Квадратные (или близкие к квадрату) JPG/PNG, как в референсе — код
обрезает/кадрирует через CSS (`object-fit: cover`), так что небольшие
отличия в пропорциях не критичны. Реальный вес файлов в репозитории не
проверялся — если фото окажутся тяжёлыми, стоит сжать их перед коммитом
(современные форматы вроде WebP тоже подойдут, но тогда нужно поменять
расширения в `PHOTO_BY_EMOJI`, `js/illustrations.js`).

# Фото наград для испытаний

Тот же приём, что и выше, только для карточек «Испытания»/«Достижения» —
код в `js/logic/challenges.js` (`getMedalForChallenge()`) и
`js/illustrations.js` (`challengeHeroForId()`, `medalHeaderPhoto()`) уже
готов их подхватить. Все 5 файлов — широкие ≈16:9 фото с наградой по
центру.

| Файл                  | Награда         |
| ---------------------- | --------------- |
| `medal_trophy.png`     | Кубок            |
| `medal_shield.png`     | Щит с галочкой   |
| `medal_crown.png`      | Корона           |
| `medal_lightning.png`  | Молния (монета)  |
| `medal_star.png`       | Звезда           |

## Как это работает

- Каждый месяц активен ровно 5 испытаний (`pickMonthlyChallenges()` в
  `js/logic/challenges.js`) — ровно столько же, сколько файлов наград,
  так что назначение всегда 1:1, без повторов внутри месяца.
  `getMedalForChallenge(id, monthKey)` решает, какой файл достанется
  испытанию `id` в месяце `monthKey`:
  - для одного конкретного месяца (`CURATED_MEDAL_MONTH_KEY` —
    Август 2026, тот, что был активен на момент подбора) — награды
    подобраны вручную по смыслу названия/описания испытания (см. таблицу
    в самой функции);
  - для любого другого месяца (прошлого или будущего — когда набор из
    11 испытаний в пуле ротируется на новую пятёрку) — детерминированная
    случайная перетасовка тех же 5 файлов, своя на каждый `monthKey`, но
    без повторов внутри одного месяца. Никакого ручного подбора при
    смене месяца не требуется.
- `challengeHeroForId(id, medalFilename)` — чисто презентационная:
  получает уже вычисленное имя файла (или `null`) и либо рендерит
  `<img src="./assets/habits/<файл>" class="challenge-hero-photo">`,
  либо — как раньше — рисованную SVG-сцену климбера (`challengeHeroXxx()`).
- Это же фото используется и на активной карточке испытания (Испытания,
  `getMedalForChallenge(id, currentMonthKey)`), и на карточке в
  Достижениях — там `getMedalForChallenge(id, info.monthKey)` берёт
  месяц, в котором испытание было пройдено/провалено (не обязательно
  текущий), так что награда в Достижениях всегда совпадает с тем, что
  показывалось на активной карточке в тот момент.
- Иконка над заголовком «Испытай себя!» — отдельная функция
  `medalHeaderPhoto()`, всегда `medal_star.png`, в том же 72×72 слоте,
  где раньше была SVG-медаль (`medalIllustration()`) — не связана с
  назначением наград на карточках.
- Все 5 файлов уже ≈16:9 с наградой по центру, поэтому кадр в широкой
  карточке (`.challenge-hero-photo`, `object-fit: cover;
  object-position: center` в `css/illustrations.css`) — один общий
  рецепт на всех, без индивидуальной подгонки под каждый файл.
- Если файл отсутствует или не грузится — `wirePhotoFallback()`
  (вызывается в `challengesView.js`/`achievementsView.js` после каждого
  рендера) подменяет `<img>` на нарисованную SVG-сцену испытания или на
  `medalIllustration()` для шапки — карточка никогда не остаётся со
  сломанной картинкой.
